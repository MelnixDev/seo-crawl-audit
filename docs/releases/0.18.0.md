# SEO Crawl Audit 0.18.0

Retry only failed URLs from one or more local snapshots. This release adds the CLI `retry` command and `retryFrom`, `retryStatuses`, `retryNetworkErrors` parameters to the existing MCP plan/scan tools; the plugin still exposes eight tools.

For the Balachky incident, the original audit recorded 181 HTTP 503 responses. The new workflow can select just those URLs from the existing batched snapshots, preserving their observed query strings and trailing slashes. No temporary sitemap or full recrawl is needed. A repeat response is an observation, not proof of Google indexing or a permanent fix.

Default selection is previous HTTP 400–599 and network failures, excluding robots exclusions. A status filter such as `[503]` excludes network errors unless explicitly enabled. Default page budgets remain 100; select a larger budget or CLI `--all` explicitly. Robots policy remains enabled unless explicitly overridden. Redirects/retries and robots requests can make HTTP request counts exceed the selected page count.

Outputs use separate retry snapshot/report/checkpoint defaults. Original snapshots cannot be overwritten by retry artifacts, including through symlink aliases. Checkpoints and large-scan confirmation tokens are bound to the selection. Empty selections request no website pages or metadata. Retry snapshots and reports explicitly represent a subset; they do not mark unchecked pages missing or resolved. Existing normalized legacy paths cannot be reconstructed.

The CLI, MCP/native archives and core share the same selection and bounded frontier. Interactive client GUI behavior is not changed by this release. See [the retry guide](../retry.md).
