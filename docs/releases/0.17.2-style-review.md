# 0.17.2 style review

Independent review on 2026-11-14 accepted the shared default identity and the
provided desktop/mobile browser captures. The approved product website is the
reference; data-heavy screens intentionally use smaller type and denser layouts
than its marketing hero.

## Reviewed

- One JSON token source supplies website CSS and private core/CLI modules.
  Palette, offline font stacks, spacing, control boundaries and semantic colors
  agree. No public core export, private cross-package import or remote font
  dependency was added.
- Actual captures covered local app idle, missing-Playwright error and completed
  HTTP scan states; report overview, Pages, Site Metrics, Issues and page-details
  dialog on desktop/mobile. They show the coral crab, navy text, neutral surfaces,
  restrained borders and rounded typography together, rather than the former
  blue floating-card theme.
- Mobile fields and navigation remain readable, tables stay in their scrolling
  containers, details wrap, and focus rings are visible. Report and app frame
  geometry now follows the same outer-container and gutter semantics as the site;
  compact embedded previews retain their intentional smaller gutter.
- Error, warning, info and success keep distinct semantic colors. Coral action
  fills use ink text; ordinary links use ink. Graph tracks use the pale wash so
  default coral remains distinguishable.
- Valid custom report colors retain sanitized input and contrasting foregrounds.
  Generated HTML for a white primary color has black text plus an ink border on
  selected report navigation, lifecycle tabs and chart filters; selection no
  longer disappears against the white background.
- The small premium polish is limited to a coral panel rule, tabular metrics,
  status dot and color/border hover transitions. Status text remains present, and
  reduced-motion rules disable the transitions. No navigation or scan flow was
  redesigned for decoration.
- Fresh captures also covered white agency branding, empty and partial reports,
  desktop/mobile comparison, and the corrected severity legend. White agency
  navigation remains visibly selected; partial results disclose both incomplete
  scan and comparison coverage. Mobile comparison stacks the run cards and wraps
  coverage text without visible page clipping in the supplied viewport.
- The corrected busy state uses an opaque neutral Scanning… button with a small
  static ring and an understated Stop action. Pending counters show dashes rather
  than findings from the previous scan. A VM test runs the production runtime
  through initial results, planning, scanning, completion and idle, checking new
  counts, action visibility, aria-busy, progress and report replacement.

## Evidence and limits

The independent focused source/generator/report checks passed 14/14; the final
app/report/design focused run passed 33/33. Shared contrast tests cover normal
text at 4.5:1 and interactive boundaries/focus at 3:1. This review does not replace
whole-repository, package-budget, multi-platform CI or public-download checks.
The subsequent focused correction run, including the VM regression, passed 15/15
according to the release operator's test log.

The reviewer inspected saved browser captures rather than controlling a second
concurrent browser session. The later busy, comparison and analytics captures
show the corrections above; they do not certify content below the captured
regions. Final completed-state recapture, screenshot/video refresh and byte
verification belong to the release operator's separate acceptance record, as do
interactive history/comparison behavior and whole-repository checks. Agency-white
was checked in generated HTML/CSS and an actual mobile report capture; native
client settings UI was not inspected.

No native Codex/Claude GUI plugin-picker rendering is certified by this review.
The native Codex CLI loader test and standalone report/app styling are distinct
checks. Published 0.17.1 remains immutable; this visual update is a subsequent
release. Demonstration data must stay labelled, and every public screenshot and
video must come from the final interface without personal workspace data.
