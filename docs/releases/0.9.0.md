# SEO Crawl Audit 0.9.0

Version 0.9.0 adds a local agent interface while keeping the crawler fully
open-source, local-first, and independent from hosted services.

Highlights:

- a bundled STDIO MCP server is available through `seo-audit mcp` and the
  `seo-audit-mcp` executable;
- `seo_audit_plan`, `seo_audit_scan`, `seo_audit_check`,
  `seo_audit_compare`, `seo_audit_issues`, `seo_audit_report`, and
  `seo_audit_rules` expose compact, structured workflows to compatible agents;
- `seo-audit agent-init --platform codex|claude|opencode|all` prepares
  project-scoped MCP configuration and installs a portable audit skill;
- existing agent configuration is never overwritten unless `--force` is
  explicitly supplied; an exact configuration snippet is printed instead;
- all output, snapshot, report, and checkpoint paths stay inside the selected
  workspace;
- protected-site headers come only from a named environment variable, are sent
  only to the audited origin, and never appear in tool results or artifacts;
- interrupted requests use the engine's AbortSignal and partial/checkpoint
  behavior rather than discarding completed work;
- issue results support severity, rule, owner, lifecycle, text, offset, and
  limit filters.

Compatibility:

- SnapshotV2, configuration schema, rule IDs, fingerprints, and rule-set
  version `1.1.0` are unchanged;
- existing CLI commands, flags, JSON/HTML outputs, Action inputs, and standard
  exit codes remain compatible;
- Node.js `>=20.19` remains the minimum local runtime, regardless of the audited
  website's implementation language or framework;
- `@seo-crawl-audit/core`, `@seo-crawl-audit/action`, and
  `@seo-crawl-audit/mcp` remain private workspaces; only the self-contained
  `seo-crawl-audit` package is published;
- no cloud service, account, telemetry, subscription, or paid functionality is
  introduced.
