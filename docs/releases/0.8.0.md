# SEO Crawl Audit 0.8.0

Version 0.8.0 completes the local project-setup and protected-site workflow.
It adds guided initialization, actionable diagnostics, and one safe
environment-based authentication model across the CLI and GitHub Action.

Highlights:

- `seo-audit init` creates a validated config, recommends local runtime files
  for `.gitignore`, and can generate manual, scheduled, or pull-request GitHub
  Actions workflows;
- existing config and workflow files are not replaced without confirmation or
  an explicit `--force`;
- `seo-audit doctor` validates Node.js, configuration, output access, homepage,
  robots.txt, and sitemap readiness without crawling linked HTML pages;
- `--offline` keeps doctor diagnostics entirely local;
- `--headers-env` enables authenticated `doctor`, `scan`, and `check` commands;
- the GitHub Action accepts the same named-environment-variable pattern through
  its `headers-env` input;
- credentials are restricted to the configured target origin and are not
  serialized into snapshots, checkpoints, history, reports, or JSON output;
- authenticated interrupted scans have a separate checkpoint namespace derived
  from the environment variable name, never its secret value;
- npm releases now use GitHub Actions trusted publishing with short-lived OIDC
  credentials and provenance.

Compatibility:

- SnapshotV2 and the configuration schema remain unchanged;
- rule IDs, severities, fingerprints, and rule-set version `1.1.0` remain
  unchanged;
- existing commands, flags, HTML/JSON contracts, and standard exit codes remain
  compatible;
- Node.js `>=20.19` remains the minimum runtime for the local CLI only; audited
  websites can use any server stack;
- no hosted service, telemetry, account, billing, or paid functionality is
  introduced;
- `@seo-crawl-audit/core` and `@seo-crawl-audit/action` remain private npm
  workspaces; only the self-contained `seo-crawl-audit` CLI is published.
