# SEO Crawl Audit 0.7.0

Version 0.7.0 adds release-oriented comparisons and makes repeated audit
results easier to understand over both page templates and time.

Highlights:

- `seo-audit compare` scans production and the corresponding preview paths,
  then reports only regressions introduced by the preview deployment;
- protected deployments can receive headers from named JSON environment
  variables without serializing their values into snapshots, reports,
  checkpoints, or command output;
- repeated findings are grouped by inferred route templates such as
  `/products/:slug`, with stable placeholders for IDs, UUIDs, dates, and
  hashes;
- the bilingual HTML dashboard includes a page-template chart and filter;
- completed scans and checks keep local SnapshotV2 history under
  `.seo-audit/history/` by default;
- `seo-audit history` lists local runs, renders trend reports, and can compare
  any two selected snapshot files without crawling;
- trend reports show severity totals, new and resolved issues, page and sitemap
  counts, and maximum crawl depth;
- new public APIs include `groupIssuesByTemplate()` and
  `buildHistorySeries()`, plus local history adapters in `core/node`.

Compatibility:

- SnapshotV2 remains unchanged;
- existing rule IDs, rule-set version `1.1.0`, and issue fingerprints remain
  stable;
- existing CLI commands, flags, reports, config precedence, and exit codes are
  preserved;
- no cloud service, telemetry, account, billing, or paid functionality is
  introduced;
- `@seo-crawl-audit/action` remains private on npm and is distributed only
  through GitHub release tags.
