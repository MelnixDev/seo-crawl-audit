## Choose a client

[Full installation, update and removal guide](../native-plugins.md).

**Codex:** unpack the ZIP outside your audit workspace, configure its explicit
workspace, then import through a local marketplace. The installation remains
bound to that root when a chat changes projects. Tools require the matching
absolute workspace, and missing/mismatched arguments fail before crawl/write.
Use a separate package and uniquely named marketplace per audit workspace.

**Claude Code:** load the unpacked plugin from outside the audited project with
`claude --plugin-dir /absolute/unpacked-plugin`, or use a local marketplace. The
launcher binds to `CLAUDE_PROJECT_DIR`; the shared skill is available as
`/seo-crawl-audit:seo-crawl-audit`.

**Claude Desktop:** open the MCPB and select an existing audit directory. This
required directory is the extension’s workspace boundary. MCPB adds a server,
not Claude Code slash commands. The local candidate is unsigned; organization
policy may prevent its installation.

The package and workspace must be disjoint: neither may contain the other.
This protects installed runtime files even if a broad parent directory is
selected. Artifact paths stay relative to the workspace; absolute paths,
traversal, Windows UNC/cross-volume escapes and escaping symlinks are rejected.

## First audit

Ask the agent to plan the URL and show its scope, then scan up to 100 pages while
respecting robots.txt. Inspect findings with URL evidence and pagination, then
request the HTML report path. Include the configured absolute workspace in a
Codex prompt. Larger scans retain the existing parameter-bound confirmation.

All runtime JavaScript dependencies are bundled. There is no runtime npm fetch,
SEO service account or SEO API key. Optional JavaScript rendering needs
Playwright and Chromium installed in the consumer workspace; this package does
not download a browser automatically.

The crawler runs locally and requests the site you select. Artifacts remain in
the audit directory. Your AI client receives tool results and applies its own
data-handling policies. Partial coverage is partial evidence; findings do not
establish Google indexing, rankings, traffic or complete site coverage. There
is no opaque overall SEO score.

## Verification and remaining gates

Final macOS candidate verification: 198/198 repository tests passed serially, including the six extracted-archive adapters and Windows UNC/install-overlap regressions. Lint and the v0.17.0 version verifier passed.

Canonical Agent Plugins JSON Schemas and the official MCPB validator check the
manifests. Actual STDIO tests extract each archive and exercise initialize,
eight-tool discovery, plan, fixture scan, filtered/paginated issues and report
creation, including rejected workspace/path escapes and update retention.

Real report screenshots and the video show a bundled-MCP run against a
three-page local fixture with deliberate metadata issues. They do not depict
installed Codex, Claude Code or Claude Desktop UI. The source fixture and tool
transcript accompany the media evidence.

Codex CLI 0.167.0-alpha.4.1 successfully added the marketplace, installed/listed
0.17.0, initialized its installed-cache runtime with all eight tools and removed
it in an isolated task-only `CODEX_HOME`. The real user config hash was unchanged.
This establishes native CLI import/cache/removal, not a GUI or agent-driven scan.

Interactive GUI installation and first use remain unverified in all three
clients. macOS runtime tests and deterministic Windows path tests do not replace
a Windows client installation. Public release remains pending independent
review, final version/package gates and the stated client-installation limits.
