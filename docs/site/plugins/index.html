Know what was verified.

Runtime and client boundaries

The published npm CLI and MCP workflow have been exercised against real downloads. Native-package schema and archive checks verify packaged paths and bytes. Native Codex CLI loader testing verifies skill icons, all eight tools and an actual bounded scan with an empty inherited PATH.

Interactive GUI installation and Claude client workflows remain separate verification steps. No public marketplace listing or platform approval is implied.

Artwork and local artifacts

Packages carry the same crab artwork in client metadata. Support differs by client: Claude Code’s directory icon field is ignored at runtime. Metadata validation does not prove every picker renders an icon.

The crawler requests your chosen site. Audit artifacts stay in the configured workspace, while the AI client handles tool results under its own policies. Read branding support notes.

What does a crawl tell me about indexing?

It reports observed URLs and rule findings within the selected scope. It cannot establish Google indexing, rankings or complete site coverage. Review heuristics in context and use Search Console for indexing evidence.

Does the package download a browser or install npm dependencies at runtime?

The native archives contain their JavaScript runtime dependencies. Optional browser rendering requires Playwright and Chromium installed separately in the consumer workspace. Default scans use returned HTML.

Can I audit a different workspace after installing?

A configured Codex copy stays bound to its explicit workspace. Use the documented configuration and reinstall flow to change it. Workspace and plugin directories must not overlap. The server rejects calls that name another workspace.
