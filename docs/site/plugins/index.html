From crawl to a verifiable fix

  1. Plan the scopeStart with 100 pages and respect robots.txt. Review the URL and coverage before crawling.
  2. Inspect the findingFilter issues, read the URL evidence and open the generated HTML artifact.
  3. Compare after a changeSave versioned JSON snapshots. Check comparable coverage before calling a finding resolved.

Know what stays local

The crawler runs on your machine and sends HTTP requests to your chosen site. Audit artifacts remain in the configured workspace. Your AI client receives tool results under its own data-handling policies.

Default scans inspect returned HTML. Optional JavaScript rendering requires Playwright and Chromium in the consumer workspace. A crawl does not establish Google indexing, rankings, traffic or complete site coverage.

Workspace and plugin directories must not overlap. Codex tools require the explicitly bound workspace; Desktop requires a directory picker. Absolute output paths, traversal, escaping symlinks and Windows UNC/cross-volume escapes are rejected.

The candidate has schema, package and actual STDIO runtime validation. Codex CLI import, installed-cache initialization and removal passed in an isolated configuration. These checks do not prove interactive GUI installation. The Desktop bundle is unsigned, and no public marketplace listing or platform approval is implied.

Start with a small audit
